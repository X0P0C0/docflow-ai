# 前端错误处理说明

## 目标

统一前端在请求失败、权限不足、会话失效和 fallback 场景下的处理方式。

## 当前原则

- 真实接口优先
- 必要时允许 fallback
- 错误信息尽量对用户可感知
- 不让错误悄悄吞掉

## 主要场景

### 1. 未登录或会话失效

- 清理本地会话
- 跳回登录页
- 尽量带上重定向来源

### 2. 权限不足

- 不直接白屏
- 跳转到可访问页面
- 用明确原因提示用户

### 3. 接口失败但允许演示兜底

- 保留页面可继续浏览的能力
- 清楚区分这是 fallback，不是真实数据

### 4. 表单提交失败

- 给出明确错误提示
- 保留用户已输入内容

## 当前实现状态

当前项目已经覆盖：

- 登录失败与会话失效处理
- 权限不足跳转
- 运行模式识别
- 部分页面的 fallback 兜底

## 后续建议

- 统一错误提示文案语气
- 统一页面级空态、错态和加载态
- 把关键业务错误码与页面行为进一步绑定
