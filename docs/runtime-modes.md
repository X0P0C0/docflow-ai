# DocFlow AI 运行模式说明

## 目的

这份文档用于说明当前项目中的运行模式边界，避免把演示数据、联调数据和真实业务数据混在一起理解。

阅读这份文档时，建议结合：

- [README.md](D:\java\project\docflow-ai\README.md)
- [development-handoff.md](D:\java\project\docflow-ai\docs\development-handoff.md)
- [frontend-delivery-demo-guide.md](D:\java\project\docflow-ai\docs\frontend-delivery-demo-guide.md)

## 1. 演示模式

### 定义

演示模式指前端没有成功接入真实后端，或者当前会话使用的是本地演示账号与演示 token。

### 当前判断方式

- 前端 `token` 为空
- 或者 `token` 以 `demo-token:` 开头

相关文件：

- [frontend/src/auth.ts](D:\java\project\docflow-ai\frontend\src\auth.ts)
- [frontend/src/utils/runtimeMode.ts](D:\java\project\docflow-ai\frontend\src\utils\runtimeMode.ts)

### 当前行为

- 登录页允许直接使用演示账号进入
- 页面会明确显示当前是演示模式
- 前端优先展示本地 mock / fallback 数据
- 部分页面允许依赖本地草稿、seed 数据或临时演示流继续工作

### 适用场景

- 后端未启动时预览页面
- 演示时快速进入系统
- 前端独立开发时避免白屏

### 风险

- 看到的数据不代表数据库真实状态
- 页面可见结果不一定等于真实后端能力
- 演示 token 不能等同于正式登录状态

## 2. 联调模式

### 定义

联调模式指前端已经连上真实后端，但仍保留“接口失败时回退到本地 mock / fallback”的兜底行为。

### 当前行为

- 登录优先走真实 `/api/auth/login`
- 列表、详情等页面优先请求真实接口
- 当接口失败时，部分页面仍可能回退到本地 mock 数据

### 适用场景

- 前后端并行开发
- 后端接口未全部完成
- 本地服务偶发不可用，但前端仍需继续推进

### 风险

- 同一页面可能出现“部分真实、部分兜底”的混合感知
- 排查问题时必须先确认当前看到的是接口数据还是本地数据

## 3. 真实后端模式

### 定义

真实后端模式指登录、鉴权、读取、写入都以真实后端接口和真实数据库为准，不再依赖本地 mock 来完成核心业务闭环。

### 判断标准

- 使用真实后端登录成功
- 关键页面和关键写操作不依赖本地 mock 也能闭环
- 当前看到的数据可以追溯到真实接口与真实数据库

### 目标行为

- 登录状态来自后端 JWT
- 权限判断以后端返回的真实角色和能力为准
- 工单、知识、评论、状态流转由后端持久化
- 演示数据只作为可关闭的开发辅助，而不参与正式业务结果

## 4. 当前项目所处阶段

当前项目不是纯演示模式，也还没完全进入彻底的真实后端模式，更接近：

`联调模式 + 演示兜底并存`

具体表现：

- 后端核心接口已经存在
- 前端已经接入多条真实接口链路
- 但登录页、Dashboard、工单、知识等区域仍保留明显的 fallback 能力

## 5. 推荐约束

为了避免模式混乱，建议后续遵循这些规则：

- 规则 1：核心写操作优先真实化
- 规则 2：允许保留演示兜底，但页面必须清楚提示当前模式
- 规则 3：排查问题前先确认当前看到的是演示数据、联调数据还是真实数据
- 规则 4：新增 mock 能力时，要同步说明退出条件
- 规则 5：当某个页面已经完全真实化后，应逐步移除该页面的本地兜底

## 6. 后续收口建议

建议后续继续做这些事：

- 梳理每个页面当前属于“演示 / 联调 / 真实后端”中的哪一种
- 给关键页面补统一的运行模式说明
- 给 mock / fallback 建一份退出清单，逐步收口
- 继续收紧演示 token 和真实 token 的行为边界
