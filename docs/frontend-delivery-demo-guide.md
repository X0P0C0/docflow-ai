# 前端交付与演示指引

## 目的

这份文档用于说明当前 `DocFlow AI` 前端如何交付、演示和快速回归。

适用场景：

- 给团队或评审演示当前前端成果
- 把项目交给下一位维护者
- 在拉取新代码后快速验证主流程是否正常

## 当前前端结果

当前前端已经收敛到统一的后台工作台方向：

- 统一的应用壳层、侧边导航和顶部区域
- 工单列表、工单详情、工单创建使用同一套管理后台语言
- 知识库列表、详情、编辑页使用同一套管理后台语言
- AI Center 从展示型页面收敛为工作台概览页
- 鉴权跳转、能力守卫、demo fallback、错误提示已有单测覆盖

交付时的验证基线：

- `npm run test:unit` 通过
- `npm run build` 通过

## 推荐演示账号

推荐使用初始化账号：

- `admin / password`
  适合完整演示。可访问工单、知识管理、AI Center、系统管理等主要路径。
- `support01 / password`
  适合演示较真实的客服/支持协同流程。
- `user01 / password`
  适合演示受限能力和路由守卫行为。

如果后端暂时不可用，登录页仍可对这些账号走 demo fallback，保证前端可继续演示。

## 运行模式说明

当前演示可分为两种模式：

### 1. 真实后端模式

适用于 `backend` 已启动、`/api` 可用的情况。

适合演示：

- 真实登录
- 工单创建 / 查看 / 评论 / 指派 / 状态流转
- 知识文章创建 / 编辑 / 查看
- 工单与知识沉淀之间的来源关联

### 2. 前端 fallback 演示模式

适用于后端暂时不可用，但仍需继续演示产品结构的情况。

适合演示：

- 页面结构和导航
- 主流程入口
- 权限限制行为
- 本地草稿和 fallback 交互路径

注意：

- fallback 模式用于保证前端演示连续性，不代表真实后端联调结果

## 推荐演示路径

下面这条顺序最适合做完整演示。

### A. 登录页与模式感知

路由：

- `/login`

建议展示：

- 演示账号快捷入口
- 当前运行模式面板
- 被重定向回登录页时的原因提示

建议讲法：

- 登录页明确区分真实后端模式和 demo fallback 模式。
- 会把会话失效、无权限跳转等原因展示出来，而不是静默失败。

### B. Dashboard

路由：

- `/dashboard`

建议展示：

- 统一壳层
- 管理台风格概览卡片
- 和后续业务页之间的信息承接

建议讲法：

- Dashboard 现在更像运营工作台，而不是营销展示页。

### C. 工单列表

路由：

- `/tickets`

建议展示：

- 筛选区
- 列表 / 看板切换
- 快速筛选
- 摘要标签

建议讲法：

- 这是当前支持协同的主入口。
- 筛选和视图状态会通过路由查询参数保留下来。

### D. 工单详情

路由：

- `/tickets/:id`

建议示例：

- 从列表中打开任意初始化工单

建议展示：

- 评论
- 时间线
- 指派和状态变更
- 知识沉淀入口
- 关联知识区

建议讲法：

- 工单详情已经是核心工作页，而不是简单展示页。
- 既支持直接处理问题，也支持把经验沉淀进知识体系。

### E. 从工单进入知识沉淀

路径：

- 从 `/tickets/:id` 进入知识创建或知识编辑

建议展示：

- 从工单生成知识草稿
- 编辑页保留来源工单上下文
- 从知识详情回看工单语境

建议讲法：

- 这是当前版本最强的产品故事：工单处理和知识沉淀已经连成一条线。

### F. 知识库列表

路由：

- `/knowledge/articles`

建议展示：

- 筛选
- 卡片 / 列表切换
- 来源工单筛选
- 已发布 / 草稿 / 本地草稿摘要

建议讲法：

- 知识库页面已经和工单页面共用同一套后台结构，维护成本和学习成本都更低。

### G. 知识详情与编辑

路由：

- `/knowledge/articles/:id`
- `/knowledge/articles/:id/edit`
- `/knowledge/articles/create`

建议展示：

- 阅读辅助区与相关文章区
- 版本信息与来源工单摘要
- 编辑进度和发布检查项

建议讲法：

- 编辑页现在优先服务于稳定保存、上下文清晰和业务可继续，而不是只追求展示感。

### H. AI Center

路由：

- `/ai-center`

建议展示：

- 紧凑头部
- 推荐卡片
- 回复建议区
- 后续沉淀提醒

建议讲法：

- AI Center 已经从 hero 式展示页调整为和其他后台页一致的工作台概览页。

### I. 能力守卫

推荐账号：

- `user01 / password`

建议展示：

- 受限路由跳转
- 知识 / 系统 / AI 入口在不同能力下的差异
- 受限账号下的 profile 和 notification 行为

建议讲法：

- 权限不只是后端概念，前端也会把访问边界清楚表达出来。

## 演示前建议检查

- 如需真实接口行为，确认 `backend` 已启动
- 初始化账号可正常登录
- 前端可通过 `npm run dev` 启动
- 登录页能明确显示当前运行模式
- 工单详情可从列表正常进入
- 知识详情可从列表正常进入
- 选定账号可访问 AI Center

## 快速回归命令

如时间允许，交付或演示前建议执行：

```bash
cd frontend
npm run test:unit
npm run build
```

## 已知但不阻塞交付的问题

- 构建仍会提示大 chunk 警告，这是性能后续项，不是功能阻塞项
- 仍有少量页面保留局部 view CSS，虽然主要重复结构已抽出
- fallback 模式是有意保留的，因此少数边界行为会和真实后端模式略有区别
