# 后端错误响应规范

## 目标

统一后端错误返回结构，便于前端处理、联调排查和日志追踪。

## 基本原则

- 成功和失败都使用一致的响应外层结构
- 错误响应应尽量可读、可定位、可追踪
- 业务错误和系统错误要能区分

## 建议字段

错误响应至少应包含：

- `success`
- `code`
- `message`
- `error`
- `path`
- `timestamp`
- `traceId`

参数校验错误可额外包含：

- `errors`

## 错误分类建议

### 1. 参数错误

适用于：

- 请求体缺字段
- 参数格式错误
- 校验规则不通过

### 2. 业务错误

适用于：

- 状态流转不合法
- 数据不存在
- 权限不足
- 重复提交

### 3. 系统错误

适用于：

- 未预期异常
- 数据库故障
- 依赖服务异常

## 当前状态

当前项目已具备：

- 统一 `ApiResponse`
- 基础全局异常处理
- 基础错误字段扩展能力

## 后续建议

- 扩充错误码字典
- 统一业务异常枚举
- 让前端对关键错误码形成稳定映射
